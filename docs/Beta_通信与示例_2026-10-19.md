# Beta 0.3：连续队列 v6（2026-10-19）

本分支从 main `73198d4` 创建。main 保留旧版；Beta 更新 STM32F103 和 ROS 2 客户端，不改变 Arduino，不烧录小车主控。

## 两个示例

| 示例 | 路线 | 适用 |
|---|---|---|
| 操场 stadium | 逆向半圆 R=0.30m → 后退0.60m → 逆向半圆 → 后退0.60m并旋转+360° | 全向/麦克纳姆；最后一段是统一0x64 |
| 正方形 square | 前进0.50m、原地逆时针90°，重复四次 | 支持原地旋转的底盘 |

两端都默认请求0.15m/s、中档18，方形转速0.5rad/s。圆弧按固件曲率/加速度限制速度，操场最后直线还受旋转速度限制；请求速度不是保证恒速。以当前位置和朝向为起点，预留整条路线及车身尺寸所需空间。只运行一次，不自动循环。已有10月18日小车实测不等于本客户端已经实车验证。

### STM32

打开 `DFCom_Example/USER/Template.uvprojx`。移植用 `DFCom_PatchOnly` 的相同接口。
`HARDWARE/beta_examples.h` 中 `DF_BETA_ROUTE=1` 操场、`=2` 正方形；确认环境后把 `DF_BETA_RUN` 从0改1。初始化诊断后延时3秒，只运行一次。默认0仅诊断，不自动行驶。

新版 API 始终使用 **米、弧度、m/s、rad/s**，不受旧 `g_dfcom_unit_mode` 影响：

```c
u16 id;
if (!DFQueue_Begin()) { /* 不支持v6、队列非空或无回包：不得发运动 */ }
else {
    id = DFQueue_Linear(0.1f, 0, 0.06f, 0, DF_ACCEL_MEDIUM);
    if (!id || DFQueue_Wait(id, 10000) != 1) DFQueue_Cancel();
}
```

Begin查询能力及下一ID；每次发送等待入队确认（不是等运动结束），连续调用即可提前排队。最多跟踪8条；`Wait`消费该ID结果后才能复用本地槽。需要单条执行就每次发送后Wait；要连续就先发送整组再按ID等待。Wait返回1正常或容差内到时完成、2未知ID/超时、3设备故障。可先用Status读取process/notice；Wait成功消费结果。失败和超时尝试取消队列并发零速；线缆断开时不能保证停车命令送达。Begin与发送、Wait仅主循环调用，不在中断调用；毫秒tick和串口中断必须运行。旧Cmd_Move/WaitMoveDone保留，但不能与新队列混发。

### ROS 2

重新编译两包生成新接口：

```bash
colcon build --merge-install --base-paths . --packages-up-to dcaron_bridge
# Linux: source install/setup.bash；Windows CMD: call install\local_setup.bat
ros2 launch dcaron_bridge bridge.launch.py port:=COM6 enable_motion_actions:=true
ros2 run dcaron_bridge trajectory_sequence <示例目录>/stadium.yaml
ros2 run dcaron_bridge trajectory_sequence <示例目录>/stadium.yaml --execute
ros2 run dcaron_bridge trajectory_sequence <示例目录>/square.yaml --execute
```

示例目录是源码 `ros2/dcaron_bridge/examples/beta`，安装后 `share/dcaron_bridge/examples/beta`。无`--execute`只校验；加`--sequential`等待每段真正完成后再发下一段。默认连续、最多8条在途，最多128段一组；每组总时限默认由YAML指定60秒，用户可在配置上限内设置。

新 `/trajectory` 使用 `dcaron_interfaces/action/Trajectory`：segments数组、sequential布尔值、timeout秒；每段command/x/y/yaw/speed/angular_speed/radius/profile。反馈包含task_id、从0起segment_index、process、notice、percent。结果含success、notice和completed段数。`/motion` 单条在默认 `motion_protocol: queue` 下同样走v6；profile明确填写16..20，默认未填的0不会被误当成加速度档。旧0/1/2只在明确 `motion_protocol: legacy` 下使用。十字标保留原接口，不能夹入连续轨迹。两个action互斥，cmd_vel会打断当前任务；串口由同一节点持有。

## 线上字段

外层仍为DFLink：`DF robot host A B LEN payload FD checksum:u16LE`；校验从DF到FD累加。A=0x02。所有S32小端×10000，+X前、+Y左、yaw逆时针正。**无会话号**。

| B | payload（字节数） |
|---|---|
| 0x64直线 | X:s32,Y:s32,speed:s32,grade:u8,ID:u16（15） |
| 0x64平移+转角 | X:s32,Y:s32,speed:s32,yaw:s32,grade:u8,ID:u16（19） |
| 0x66圆弧 | R:s32,yaw:s32,signed_speed:s32,grade:u8,ID:u16（15） |
| 0x63原地转 | yaw:s32,omega:s32,ID:u16（10） |

转角为0使用15字节普通直线；ROS的0x65输入别名编码为扩展0x64。半径正，圆弧速度可负表示倒行。五档16/17/18/19/20分别极低/低/中/高/极高，对应目前固件标称线加速度0.25/0.5/1/1.5/2m/s²。控制与微调在车端完成，客户端不复刻位置PID。

例：前进0.1m，0.06m/s，中档，ID7：
`DF 01 97 02 64 0F E8 03 00 00 00 00 00 00 58 02 00 00 12 07 00 FD 47 04`。

回包A=0x6F/B=0x85，长度4，`process:u8,notice:u8,ID:u16`：

| process/notice | 意义 |
|---|---|
| 0 / 0x10 | 入队确认 |
| 1..254 / 0 | 运动进度，不算完成 |
| 254 / 0x25 | 到位，正在末端微调，不释放任务 |
| 255 / 0 | 正常完成 |
| 255 / 0x27 | 300ms微调上限到达、仍在容差内，成功完成 |
| 255 / 0x26 | 微调超差失败，不能当成功 |
| */0x11 | 队列满，原ID重试，不分配新ID |

其他notice按失败处理，不自动继续。ID0是队列整体通知，不当成单段结果；两个相同ID完成包只完成一次。失去入队ACK重发原ID原字节；已确认入队但终止丢失时查询该ID结果，不重新发新任务。

管理B=0x85：payload `[0]` 查询能力（16/0x21/版本6）；`[7]` 查询下一ID（空闲槽/0x28/ID）；`[5,ID:u16]` 查询结果；`[4]` 取消。Beta要求v6且开始时设备队列为空，不静默降级。ID自动1..65535循环，断线不重放旧任务，下一批重新查询编号。单设备只允许一个发送者；有限历史无法消除跨完整编号周期或设备重启后无限延迟的旧包。
