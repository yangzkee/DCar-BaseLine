# v4.2.10 Beta 运动对接（2026-10-29）

本仓库是外部客户端例程，车端固件通过 DFhelper 选择 Beta 升级。本次不改变 DF-Link 帧、任务ID、单位或 Odom 解码；请获取本仓库大小写准确的 `Beta` 分支。`main` 不随本次更新。

## 直走和边走边转共用接口

```c
// 中档，前进30cm，保持段起始朝向。
uint16_t a = DFQueue_Linear(0.30f, 0.0f, 0.15f, 0.0f, 18);
// 中档，段坐标系向左30cm，同时逆时针转90°。
// a确认入队后即可提交b，不要先等a完成，才能让车端预览后续段。
uint16_t b = a ? DFQueue_Linear(0.0f, 0.30f, 0.15f, 1.570796327f, 18) : 0;
// 调用前仍须DFQueue_Begin；检查非零ID后按main.c处理DONE/WARN/故障。
```

ROS使用 `command: 100`，对应字段 `x/y/speed/yaw/profile`；`101` 仍是相同0x64的输入别名。`yaw=0`发送15字节负载，非零发送19字节负载，末尾均为任务ID。平移与旋转同时推进，不要求两者同时到终点；先完成的一侧保持，等待另一侧。车端用原生角度闭环追目标，不要求客户端持续发送角速度或锁头命令。

## 档位、衔接与结束

- 档位16～20保持不变。车端默认平移加速度预算约为0.1417 / 0.4958 / 0.85 / 1.19 / 1.53 m/s²，沿用上一版；这是默认预算，不保证每时刻实际车体加速度达到该值，参考规划预留20%反馈余量，仍受限速、轮速分配及运动状态约束。
- 本次统一控制的是全向底盘0x64（含零角度直线），不代表0x63原地旋转、0x66圆弧、Arduino无ID旧接口和非全向底盘全部改为同一规划器。
- 已有后续段、当前无明确停止标志、剩余位置小于12mm且角差小于5°时，可提前交接；下一段保留原计划终点及剩余误差。它不保证直角、反向等任意组合恒速通过。
- 中间段 DONE 可能表示已完成交接，不表示车轮已停或该中间点已达到最终1mm精度。需要逐段到点停再执行时，不提前排入下一段；ROS可选 `sequential: true`。
- 最后一段完整收尾。健康、已校准的程控结束后维持锁头，正常完成保持目标角；取消/异常不再追被放弃的旋转。RC、未校准和安全接管仍优先。平移零速不等于锁头关闭，外力改变朝向时可能有角度纠正输出。
- `0x24/0x26`的v7警告语义不变，保留原码供排查，不能把警告退段当作精度验收通过。

## 验证边界

本次客户端补了全部五档、零/正/负角度线帧等价及“先入队后完成”的回归，既有STM32/ROS实现已支持这些字段，因此未改编码器或自动启动路线。主机测试不等同ROS/Arduino实车验收。

车端直线、平移转向和同向连续运动已有专项仿真及本机实测，用户确认当前体验后发布Beta。扩大回归仍存在圆弧-直线混合操场模型超时及旧末端阶段断言不匹配，不能宣称全部路线回归通过；高滞后模型仍可出现毫米级峰值超调。旧v4.2.9同一操场模型也未通过最终角度断言，但本次失败表现不同，原因尚未收敛。默认四段操场包含圆弧，需按实际底盘另行验证，不能仅凭直线验证结果放行。
